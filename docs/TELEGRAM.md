# Telegram (личный аккаунт): userbot через MTProto

JARVIS умеет работать с Telegram двумя независимыми способами — они не заменяют друг друга,
а покрывают разные задачи:

| | `jarvis_send_message` (Bot API, `messenger.py`) | `jarvis_telegram` (MTProto userbot, этот документ) |
|---|---|---|
| Протокол | Bot API токен бота (`hermes send`) | MTProto — тот же протокол, что у официального клиента Telegram/tdlib |
| От чьего имени | От имени отдельного бота | От имени **вашего личного аккаунта** |
| Может читать историю чужих чатов/личку | Нет — бот видит только сообщения, адресованные ему | Да — всё, что видно вам самим в приложении Telegram |
| Непрочитанные, медиа входящих | Нет | Да |
| Нужна настройка | Токен бота в Hermes gateway | `api_id`/`api_hash` + вход по номеру телефона (этот документ) |

## Почему MTProto-userbot, а не только Bot API

Bot API принципиально устроен так, что бот видит только то, что ему прислали напрямую — он не
может «зайти» в ваши личные переписки, посмотреть непрочитанные или прочитать историю чата, в
который его не добавляли. Это разумное ограничение для чужих ботов, но не подходит для личного
ассистента, которому нужно «посмотри, что мне написали», «сколько у меня непрочитанных»,
«ответь другу вместо меня».

Полный доступ к собственному аккаунту дают только два способа: официальный tdlib (C++/C-биндинги,
как у [alex2772/kuni](https://github.com/alex2772/kuni)) или [Telethon](https://docs.telethon.dev/) —
чистая Python-реализация того же протокола MTProto без необходимости собирать C-код (важно для
кроссплатформенности: сборка tdlib на Windows/некоторых Linux-дистрибутивах требует cmake, openssl-dev
и может занимать десятки минут — Telethon ставится одной командой `pip install telethon` везде).

**Про условия использования (важно понимать, но это не блокирует функцию):** Telegram запрещает
автоматизацию, которая имитирует человека для рассылки незапрошенных сообщений/спама или для
накрутки чужих аккаунтов без их ведома. Здесь речь о принципиально другом сценарии — **владелец
аккаунта сам, добровольно, даёт собственному ассистенту доступ к собственной переписке**, ровно
как разрешает Telegram Desktop или мобильному клиенту показывать её на экране. Ответственность за
то, как используется этот доступ (например, не рассылать через него что-либо посторонним людям без
их согласия), лежит на владельце аккаунта — как и с любым другим инструментом, дающим доступ к
личным данным (email, календарь, файлы).

## Настройка (один раз, ~3 минуты)

Как и для Google Calendar (см. docs/CALENDAR.md), Telegram требует, чтобы у каждого приложения
был свой `api_id`/`api_hash` — это бесплатно и не связано с ботами.

1. Откройте [my.telegram.org](https://my.telegram.org) и войдите под своим номером телефона
   (Telegram пришлёт код в приложение).
2. Перейдите в **API development tools**.
3. Заполните форму (любое название приложения, например «JARVIS»; платформа — Desktop).
4. Скопируйте **App api_id** (число) и **App api_hash**.
5. В терминале:
   ```bash
   jarvis telegram setup
   ```
   Вставьте `api_id`/`api_hash`, затем номер телефона (с кодом страны, например `+79991234567`) —
   Telegram пришлёт код входа в приложение/SMS, введите его. Если включена двухфакторная
   аутентификация — попросит облачный пароль. После этого:
   ```bash
   jarvis telegram status    # ✔ Авторизовано как @username
   jarvis telegram unread    # сводка непрочитанных
   ```

## Использование

- Голосом/в чате: «есть что-то непрочитанное в телеграме», «прочитай последние сообщения от Х»,
  «напиши Y в телеграме, что...», «пришли мне фото из последнего сообщения» — модель сама вызовет
  `jarvis_telegram` (dialogs/unread/read/send/send_file/download_media).
- Из терминала: `jarvis telegram unread`, `jarvis telegram dialogs [-unread]`, `jarvis telegram status`.
- `read` по умолчанию **не** отмечает сообщения прочитанными (не трогает счётчик на телефоне) —
  явно попросите «и отметь прочитанным», если нужно (`mark_read=true` в вызове инструмента, или
  отдельное действие `mark_read`).
- Если userbot ещё не настроен, JARVIS ответит одной фразой, что нужно выполнить
  `jarvis telegram setup`, и не будет переспрашивать в каждом ходе.

## Приватность и хранение

- Сессия (эквивалент входа в приложение — не пароль) хранится локально в
  `$HERMES_HOME/plugin-data/jarvis-core/telegram_userbot.session` — никогда не покидает вашу машину
  и не передаётся ни на какой сервер JARVIS/Hermes (всё общение — прямой MTProto-канал между вашим
  процессом и серверами Telegram, тот же самый, что использует официальный клиент).
- `api_id`/`api_hash` хранятся в `$HERMES_HOME/plugin-data/jarvis-core/telegram_userbot_credentials.json`
  — они привязаны к вашему собственному приложению на my.telegram.org, не к JARVIS.
- `jarvis telegram logout` выходит из аккаунта **и на стороне Telegram** (в отличие от Google
  Calendar, Telegram API поддерживает полноценный отзыв сессии), затем удаляет локальный файл сессии.
- Активные сессии (в т.ч. эту) в любой момент можно посмотреть и отозвать вручную в самом Telegram:
  Настройки → Устройства.
- По умолчанию ничего не читается и не отправляется без явного запроса пользователя — нет фонового
  «слушателя» входящих сообщений, инструмент активируется только вызовом модели по вашей просьбе.

## Диагностика

| Проблема | Решение |
|---|---|
| `telethon не установлен` | `pip install telethon` (устанавливается автоматически при `install.sh`/`install.ps1`) |
| «Код неверный или устарел» | Запросите новый через `jarvis telegram setup` заново — код Telegram живёт недолго |
| «Включена двухфакторная аутентификация» | Введите облачный пароль Telegram (не код из SMS) при запросе |
| Сессия недействительна | Возможно, отозвана вручную в Настройки → Устройства — выполните `jarvis telegram setup` заново |
| «Telegram просит подождать N секунд» | `FloodWaitError` — Telegram временно ограничил частоту запросов входа, подождите указанное время |
